# 決定の記録: site-look-plan

`candidates.md` の候補（`C01`〜`C19`。C17・C18・C19 は 4.2 の提示の場で開発者の指摘を受けて足した）ごとに、見た目の方向の推奨と、開発者の判断を記録する（Requirement 4）。材料は `mockups/README.md` の試作の記録と `screenshots/mock-*.png`（今の見た目 `base` は ukadoc-spec の `c84942a`）、`survey.md` の差（`D01`〜`D20`）である。

- 「推奨」と「推奨の理由」は、判断の材料として先に書いた案である。**決定ではない**
- 「判断」「理由」「目標」「保留」は、開発者の判断を受けるタスク（4.2）だけが、開発者の言葉に沿って書く。推奨を判断に写さない（開発者が「推奨どおり」と答えたときだけ、その旨を「判断の記録」に書いて写す）
- 「行き先」は、後続 spec への切り分け（5.1）で書く
- 推奨が「採る」の行には、目標にする画面と、どこの見え方を目指すかの案を「目標の案」として添えた。「保留」の行には、決めるのに要るものの案を「要るものの案」として添えた
- 試作で確かめられなかった候補: 無い（`mockups/README.md` の 3 頁の節とも「失敗: なし」）。C13・C16 は「試作しない」と決めた候補で、試作の画面は無い
- どの候補を採っても、`survey.md` の「失わないもの」（D15 検索・D16 ダークモード・D17 見出しへのリンク・D18 狭い画面・D19 コードのコピー・D20 記述例の字）は崩さない
