# 候補の一覧: site-look-plan

`survey.md` の差（`D01`〜`D20`）から作った、視認性の改善候補と遊びの候補である（Requirement 2）。後の試作（`mockups/README.md`）と決定（`decisions.md`）は、この一覧の候補の ID（`C01` から）を参照する。**候補の ID は付けた後で振り直さない。**

- 作った日: 2026-10-24。見込みは `research.md` の事実（「設計フェーズの調査」を含む）と、`ukadoc-spec/` のメインのチェックアウト（`0e028a4`）の `mkdocs.yml`・`assets/extra.css`・`scripts/prepare_site.py`・原稿を読んだ結果による。どれも変えていない
- 変更の種類は、`見た目の指定だけ`・`頁の組み立て`・`サイトを作る処理`・`画像を足す`・`ブラウザの仕掛け` の 5 つから選ぶ
- 試作では、候補ごとの見た目の指定を `html[data-slp~="Cxx"]` の下に書き、URL の `?slp=C01,C03` で入れたり外したりする（design.md の MockupWorkbench）。`prepare_site.py` の目印と `mkdocs.yml` の `pymdownx.highlight` は `?slp=` で切り替えられず、試作の build の全体に効く。目印は付けても、見た目の指定が無ければ見え方は変わらない
- 旧サイトの見せ方を手本にする候補でも、旧サイトの見た目の指定（`list.css`・`base.css`）は写さずに書き直す。色・寸法は今のサイトの明・暗の色（Material の色の変数）に合わせて決め直す
- 原稿（Markdown）の変更が要る候補は無い。原稿に依る部分が残るものは、その候補の「原稿」に書いた

## どの候補も守ること

`survey.md` の「失わないもの」は、どの候補を採っても崩さない。試作でも、当てはまる候補ではこれを確かめる。

- D15 検索: 頭の帯の検索の欄と、結果の頁の語の強調を隠さない・壊さない。目印や札で字を書き換えるとき（C06）も、検索で引ける字は変えない
- D16 ダークモード: 色は明・暗の両方で決め、どちらでも字と地の差が十分にある
- D17 見出しへのリンク: 見出しの id と `a.headerlink`（¶）と右の欄の目次を変えない。見出しを箱で包む候補（C04・C11）は、試作でこれを確かめる
- D18 狭い画面: 幅 375 で `scrollWidth <= innerWidth` のまま
- D19 コードのコピー: コピーのボタンを残し、コピーされる字を変えない（C10・C15 は字を色の要素で包むだけにする）
- D20 記述例の字: 記述例の `\` を `\` のまま見せる。等幅の字の指定を変えるとき（C10）は `¥` に化ける字を選ばない

## 候補

### C01
- 題: 項目名を帯で囲む
- 区別: 視認性
- 解く差: D01・D08
- 変更の種類: `見た目の指定だけ`
- 見込み: まとめ頁の項目名は `h3` なので、`.md-typeset h3` に左の太い線・下の線・薄い地を付ければ、目印なしで帯にできる。`h3` の中の `code`（`sakura-script` の項目名）の灰色の地は帯の中で消す。`descript-ghost` の項目名（`code` で囲まない `h3`）にも同じ指定が効く
- 原稿: 要らない
- 波及: サイト全体の `h3` が帯になる。まとめ頁の項目（`list/sakura-script` だけで 373 個）のほか、`spec/` や `memo/` などの頁の節の `h3` も同じ見た目になる。`list/sakura-script` の分類の中の注意書きの節の見出し 12 個（例: `h3#notes_environmentvariable`。C04・C11）も帯になるので、項目と分けるなら `h3:not([id^="notes_"])` で除く。項目だけに絞るなら、`prepare_site.py` がまとめ頁に入れる `<hr />` の直後の `h3`（`hr + h3`）に限る案を試作で見比べる
- 試作の当て先: `list/sakura-script`（位置: `#bang-lock-repaint`）

### C02

- 区別: 視認性
- 解く差: D08

- 見込み: 項目の間の `hr` の上下の余白と、`h3` の上の余白を小さくする。高さ 700 の画面に入る項目を、今の 3 から旧サイトに近い 4〜5 に増やすのが目安（`tools/shot.mjs` の同じ位置の画面で数える）
- 原稿: 要らない
- 波及: サイト全体の `hr` と `h3` の余白が変わる。`hr` の多くは `prepare_site.py` がまとめ頁の項目の間に入れたもの（`list/sakura-script` で 374 個）で、原稿に書かれた `---` も同じ見た目になる

### C04
- 題: 注意書きの節を枠の箱に入れる
- 区別: 視認性
- 解く差: D05
- 変更の種類: `サイトを作る処理`・`見た目の指定だけ`
- 見込み: 注意書きの節は原稿の `notes_*.md` の 1 単位である。`list/sakura-script` の 14 個のうち、頁の頭にあるのは 2 個（`notes_escape`・`notes_lifespan`。`h2`）で、残りの 12 個は分類の中の `h3`（例: `h3#notes_environmentvariable`）になる。どれも HTML では、その見出しから次の `<hr />` までの兄弟の要素になる。見た目の指定だけでは「次の `hr` まで」を囲めないので、`prepare_site.py` が `notes_*.md` の単位を `<div class="slp-notes" markdown="1">` で包む（`md_in_html` は有効）。見出しが `div` の中に入るので、見出しの id・¶・目次が変わらないかを試作で確かめる（D17）。包めないときの代わりは、`ブラウザの仕掛け` で読み込みの後に包む案
- 原稿: 要らない（見出しを admonition に書き換える案は原稿が要るので採らない）
- 波及: `notes_*.md` の単位はサイト全体で 16 個（`list/sakura-script` に 14 個、`list/propertysystem` に 2 個）。その全部が箱になる

### C05

### C06
- 題: 対応のベースウェアを名前ごとの札にする
- 区別: 視認性
- 解く差: D02・D09
- 変更の種類: `サイトを作る処理`・`見た目の指定だけ`
- 見込み: 旧サイトの画像の印の代わりに、ベースウェアの名前（Materia・SSP・CROW・Ninix）を 1 つずつ文字の札にする。`prepare_site.py` が `**対応:**` の段落の ` / ` で区切った名前を `<span class="slp-bw slp-bw-ssp">SSP</span>` のように包む（C05 の段落の目印も付ける）。版などの名前の後ろの字（例: `SSP 2.8.40`）は札の後ろにそのまま残す。原稿の `**対応:**` の行は 146 通り（全 1624 行）あり、そのうち形に収まらないものが 30 通り（行で 63 行）ある（` / ` で区切った各部分が「名前、または名前と空白と数字の版」でないもの。例: `Materia廃止仕様 / SSP`、`SSP (オプションは2.4～) / Ninix`）。包めない字はそのまま残し、札にしない
- 原稿: 要らない
- 素材: 旧サイトの画像の印（`icon_m.png`・`icon_s.png`・`icon_c.png`・`icon_n.png`）は再利用の許可が明記されていないので使わない。画像の印にしたいときは `画像を足す` が加わり、画像は管理者の確認が要る（問い合わせは画像を採る後続 spec で開発者が行う）。試作は文字の札だけにする
- 波及: `**対応:**` の段落のある全頁（`slp-support` の目印が付く 1623 段落。build の `<p><strong>対応:</strong>` は 1624 個あるが、`dev/nar.md` の 1 個は `prepare_site.py` のまとめ頁の後処理（`unit_body`）を通らないので目印が付かない）。札の色はベースウェアの見分けの補助で、名前の字を残すので色だけに頼らない。検索の字は変わらない（`span` で包むだけ）
- 試作の当て先: `list/sakura-script`（位置: `#bang-lock-repaint`）

### C08
- 題: 記述例をひとかたまりの箱に見せる
- 区別: 視認性
- 解く差: D03
- 変更の種類: `見た目の指定だけ`
- 見込み: `h4`「記述例」を箱の頭の帯にし、続くコードブロック（`h4 + .highlight`・`.highlight + .highlight`）の上下の余白を詰めて同じ枠の色でつなぐ。1 つの要素で囲むわけではないので、箱は見た目の上だけのかたまりになる。本当に 1 つの箱にするなら `サイトを作る処理`（`prepare_site.py` が記述例の節を `div` で包む）が加わる。`list/sakura-script` の `h4` はほとんどが「記述例」の見出し（原稿の `## 記述例` が 255 個。ほかの `##` は 5 個）で、記述例でない `h4` の後のコードも同じ見た目になる
- 原稿: 要らない
- 波及: サイト全体の `h4` の直後のコードブロックと、続けて並ぶコードブロックに効く。`h4` の後がコードでない節や、ほかの頁で続けて並ぶコードブロックも同じ見た目になる
- 試作の当て先: `list/sakura-script`（位置: `#bang-lock-repaint`）

### C09
- 題: コピーのボタンの下に字を重ねない
- 区別: 視認性
- 解く差: D03・D19
- 変更の種類: `見た目の指定だけ`
- 見込み: `assets/extra.css` の `.md-typeset pre > code` は折り返し（`pre-wrap`）にしているので、長い行が右上のコピーのボタンの下まで伸びる。コードの右の内側の余白をボタンの幅の分だけ広げる。C10 を採ると HTML の形が `pre.highlight > code` に変わるので、指定はどちらの形にも効く書き方にする
- 原稿: 要らない
- 波及: サイト全体のコードブロック 449 個（言語指定のある 287 個と無い 162 個）の右の余白が広がる。どれも 1 行に入る字の数が少し減る
- 試作の当て先: `list/sakura-script`（位置: `#bang-lock-repaint`）

### C10
- 題: さくらスクリプトに色を付ける
- 区別: 遊び
- 解く差: 差なし（遊び）
- 変更の種類: `サイトを作る処理`・`ブラウザの仕掛け`・`見た目の指定だけ`
- 見込み: 今は ```` ```sakurascript ```` の言語名が HTML に残らない（`language-*` の class が 0 個）。`mkdocs.yml` に `pymdownx.highlight` を `use_pygments: false` で足すと、287 個が `<pre class="highlight"><code class="language-sakurascript">` になり、ブラウザの小さな自作の仕掛けで、タグ（`\0`・`\s[10]`・`\![raise,…]`）と変数（`%username` など）とを色の要素で包める。もう 1 つの道は Pygments のさくらスクリプトのレキサーを入れることで、これは新しい依存（`requirements.txt`）になる。`pymdownx.highlight` は入っている pymdown-extensions の一部だが、Markdown 拡張を足す改造なので、見た目の改造とは別の spec に切り分ける（Requirement 5.5）。着色は色を付けるだけで、色が見えなくても今と同じに読める
- 原稿: 要らない
- 波及: `highlight` を有効にすると、コードブロック 449 個すべての HTML が `<div class="highlight"><pre><span></span><code>` から `pre.highlight > code` の形に変わる。うち言語指定の無い 162 個（`manual/ghost` のファイル構成の木や、`\![vanishbymyself]` の記述例を含む）は言語の印が付かず、色も付かない。`assets/extra.css` の `pre > code` の折り返しと、コピーのボタン（C09・D19）の見え方を確かめ直す。仕掛けが動かない環境では色が付かないだけで、今と同じに読める
- 条件:
  - 字の太さ・幅・大きさを変えない（折り返しの位置が変わらない）。等幅の字で `\` が `¥` に化けない（D20）
  - 明るい表示とダークモードの両方で、色を付けた字と地の差が十分にある
  - 色の数を絞る（タグ・変数・地の文の 3 つほど）。本文の読み取りを妨げる派手な色や背景の色を使わない
  - コピーされる字を変えない（D19）
- 試作の当て先: `list/sakura-script`（位置: `#bang-lock-repaint`）

- 原稿: 要らない
- 波及: `notes_*.md` の単位 16 個（C04 と同じ）と、admonition 14 個（`descript/shell-surfaces`・`dev/nar`・`dev/shell`・`dev/update`・`manual/install`・`manual/shell` の頁）

  - 本文の字の大きさ・行間を変えない。尻尾が本文の字に重ならない
  - 明るい表示とダークモードの両方で、枠と地と字の差が十分にある
  - 注意書き・警告であることが、吹き出しの形でも見て分かる（warning は警告と分かる色を残す）
  - 見出しの id・¶・目次を変えない（D17）
- 試作の当て先: `list/sakura-script`（位置: `#notes_escape`）

### C12
- 題: キャラクターを頁に出す
- 区別: 遊び
- 解く差: D14
- 変更の種類: `頁の組み立て`・`画像を足す`・`見た目の指定だけ`
- 見込み: 旧サイトの `manual_*.html` の頭のキャラクターの絵に当たるものを、テンプレートの上書きで置く。`theme.custom_dir: overrides` の `main.html` で `{% block content %}` に `{{ super() }}` と絵の要素を足す（Zensical 0.0.67 で通ることを確かめ済み）。置き場所は本文の上の右の余白か、頁の右下の隅で、本文の幅を狭めない。`manual/` の頁だけに出すか、全頁に出すかは試作で見比べる
- 原稿: 要らない
- 素材: 旧サイトのキャラクターの絵・画像のボタン・地の画像（`shade_v.png`・`shade_h.png`）は再利用の許可が明記されていない。使うなら管理者の確認が要る（問い合わせは画像を採る後続 spec で開発者が行う）。試作は自作の仮の画像 `assets/image/slp-*` だけで行い、本番の絵（新しく描くか、許可を得て使うか）は後続 spec で決める
- 波及: `content` ブロックを上書きすると、絵を出す頁の全部（全頁に出すならサイト全体）に要素が足される
- 条件:
  - 本文・目次・頭の帯（検索・明暗の切り替え。D15・D16）に重ならない。本文の読み取りを妨げない
  - 明るい表示とダークモードの両方で、絵の輪郭が地に溶けない
  - 幅 375 では隠すか小さくし、横にはみ出さない（D18）
  - 飾りとして扱い、読み上げに出さない（`alt=""`）。動かすなら `prefers-reduced-motion` で止める
- 試作の当て先: `manual/ghost`（位置: `h1#ゴースト`）

### C13
- 題: 記述例を手元のゴーストで再生する
- 区別: 遊び
- 解く差: D04
- 変更の種類: `ブラウザの仕掛け`・`頁の組み立て`・`サイトを作る処理`
- 見込み: 旧サイトの `sakura_player.js` と同じく、記述例ごとに「実行」ボタンを付け、選んだゴーストへ `OnUkadocScriptExample` を SSTP で送る。記述例を見分けるには言語の印が要るので、C10 と同じ `pymdownx.highlight` の設定（`サイトを作る処理`）に依る。印が付けば `code.language-sakurascript` の 287 個が対象になり、旧サイトで `noplay` だった `\![vanishbymyself]` の 1 例は原稿で言語指定が無いので、自然に対象の外になる。ゴーストを選ぶ欄と「読み込み」ボタンは、テンプレートの上書き（`頁の組み立て`）で置く。実用（記述例をその場で試す）にもまたがる
- 原稿: 要らない
- 素材: 旧サイトの `sakura_player.js` は再利用の許可が明記されていない。流用せず書き直す
- 波及: `list/sakura-script` の頁だけに出す（ほかの頁の記述例は対象にしない）。`highlight` の波及は C10 と同じ
- 論点:
  - 利用者の操作を起点にする: 頁を開いただけでは何も読み込まず、何も送らない。「読み込み」ボタンを押したときに初めて読み込み、ゴーストの一覧を取る。送るのは「実行」ボタンを押したときだけ
  - 外部の読み込みの扱い: 旧サイトは jsstp を `https://cdn.jsdelivr.net/gh/ukatech/jsstp-lib@v3.1.1.2/dist/jsstp.mjs` から読む。サイトの `assets/` に版を固定して置くか（ライセンスと更新の扱いが要る）、CDN から読むなら利用者の操作の後にだけ読むか、を決める
  - 送る中身: 危険なタグ（ゴーストの削除など）は `OnUkadocScriptExample` に対応したゴーストでしか実行されない旨の説明を、旧サイトと同じくボタンの近くに置く
- 条件:
  - ボタンが記述例の読み取りとコピー（D19）を妨げない。「読み込み」の前はボタンを出さない
  - SSP の無い環境・狭い画面（D18）では、何も出ないか、邪魔にならない
  - 明るい表示とダークモードの両方で、ボタンが読める
- 試作の当て先: 試作しない（公開サイトから手元のベースウェアへ送り、外部のスクリプトを読む仕掛けで、Requirement 2.7 と design.md の Security Considerations により、この spec では試作しない。論点を後続 spec の brief に渡す）

### C14
- 題: ファイルごとの説明の切れ目を見せる
- 区別: 視認性
- 解く差: D12・D11
- 変更の種類: `見た目の指定だけ`・`頁の組み立て`
- 見込み: `manual/ghost` のファイルごとの箇条書き `**ファイル名**: 説明` を、ファイル名を 1 行に置いて説明を字下げする形と、ファイルの間の細い線に見せる（`li > p:first-child > strong:first-child` を `display: block` にするなど）。同じ形の箇条書き（頭が太字の名前）は `spec/shiori3` のヘッダ（D11）や、ほかの頁の箇条書きにもあるので、見た目の指定だけでは効く頁を絞れない。絞るには、テンプレートの上書きで本文の要素に頁の種類の印（例: `manual/` の頁）を付ける（`頁の組み立て`）。試作では `:has(h1#ゴースト)` で頁を絞ってよい
- 原稿: 要らない。ただし `updates2.dau` と `updates.txt` が 1 つの説明を共有している見え方（D12）は原稿の書き方によるもので、この候補では直らない（直すには原稿が要るので、この計画では扱わない。`survey.md` の「見た目の外の問題」）
- 波及: 印を `manual/` の頁に付けるなら `manual/*` の 8 頁。印を付けずに全体に効かせると、頭が太字の箇条書きのある全頁（`spec/shiori3` のヘッダの箇条書きを含む。D11 にも効く）
- 試作の当て先: `manual/ghost`（位置: `h1#ゴースト`）

### C15
- 題: ファイル構成の木でファイル名に色を付ける
- 区別: 視認性
- 解く差: D13
- 変更の種類: `ブラウザの仕掛け`・`見た目の指定だけ`
- 見込み: ファイル構成の木は言語指定の無いコードブロックで、中の字に目印を付けられない（見た目の指定だけでは字ごとに色を変えられない）。ブラウザの小さな自作の仕掛けで、`+-` で始まる行の名前を見て、拡張子のあるもの（`descript.txt`・`*.ico` など）をファイル、無いもの（`(myghost)`・`ghost`・`master`）をフォルダとして、ファイル名を色の要素で包む。サイトを作る処理で木を HTML の `<pre>` に書き換える案もあるが、コピーのボタンとコードブロックの見た目から外れるので採らない
- 原稿: 要らない
- 波及: `+-` の行を含むコードブロックだけに効く（`manual/` の頁のファイル構成の木）。仕掛けが動かない環境では今のまま
- 試作の当て先: `manual/ghost`（位置: `h1#ゴースト`）

### C16

## 両立しない組

同じ部分に別の見せ方を当てる候補の組である。決定の段（`decisions.md`）で、組ごとにどちらか 1 つ（または両方を採らない）を選ぶ。

| 組 | 同じ部分 | 違い |
|---|---|---|
| C04 と C11 | `list/sakura-script` などの注意書きの節（`notes_*.md` の単位 16 個） | C04 は点線の枠の箱（視認性）、C11 は尻尾の付いたバルーン（遊び）。どちらも `div.slp-notes` で包む同じ目印を使う |
| C05 と C06 | 対応ベースウェアの段落（1623 段落） | C05 は段落ごと 1 本の帯、C06 はベースウェアの名前ごとの札。どちらも `slp-support` の目印を使う |
| C08 と C18 | 記述例の `h4` と続くコードブロック | C08 は灰色の細い枠の控えめな箱、C18 は濃い緑の帯と左の太い線の強い箱 |

## 重ねるときの依存

両立はするが、片方がもう片方の HTML の形や目印に依る組である。後続 spec への切り分け（同じファイルを触る spec の順）の材料にする。

- C10 → C13: C13 の記述例の見分けは、C10 の `pymdownx.highlight` の設定（言語の印）に依る
- C10 → C09: C10 でコードブロックの HTML の形が変わるので、C09 の指定は両方の形に効くようにする
- C05 → C06: C06 は C05 の段落の目印（`slp-support`）を付けたうえで名前を包む。どちらも `prepare_site.py` の同じ後処理を触る
- C04・C11 と C03・C01: C03 は `notes_` の `h2` を、C01 は `notes_` の `h3`（分類の中の 12 個）を除く。C04・C11 を採らないときも、この除き方はそのままでよい
- C12 → C11: C11 の尻尾の先の絵は、C12 の絵を採ったときだけ足す
- C14 と C16: 頁の種類の印（テンプレートの上書き）を共有できる
