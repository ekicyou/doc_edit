## どの候補も守ること

`survey.md` の「失わないもの」は、どの候補を採っても崩さない。試作でも、当てはまる候補ではこれを確かめる。

- D15 検索: 頭の帯の検索の欄と、結果の頁の語の強調を隠さない・壊さない。目印や札で字を書き換えるとき（C06）も、検索で引ける字は変えない
- D16 ダークモード: 色は明・暗の両方で決め、どちらでも字と地の差が十分にある
- D17 見出しへのリンク: 見出しの id と `a.headerlink`（¶）と右の欄の目次を変えない。見出しを箱で包む候補（C04・C11）は、試作でこれを確かめる
- D18 狭い画面: 幅 375 で `scrollWidth <= innerWidth` のまま
- D19 コードのコピー: コピーのボタンを残し、コピーされる字を変えない（C10・C15 は字を色の要素で包むだけにする）
- D20 記述例の字: 記述例の `\` を `\` のまま見せる。等幅の字の指定を変えるとき（C10）は `¥` に化ける字を選ばない

## 候補

### C01
- 題: 項目名を帯で囲む
- 区別: 視認性
- 解く差: D01・D08
- 変更の種類: `見た目の指定だけ`
- 見込み: まとめ頁の項目名は `h3` なので、`.md-typeset h3` に左の太い線・下の線・薄い地を付ければ、目印なしで帯にできる。`h3` の中の `code`（`sakura-script` の項目名）の灰色の地は帯の中で消す。`descript-ghost` の項目名（`code` で囲まない `h3`）にも同じ指定が効く
- 原稿: 要らない
- 波及: サイト全体の `h3` が帯になる。まとめ頁の項目（`list/sakura-script` だけで 373 個）のほか、`spec/` や `memo/` などの頁の節の `h3` も同じ見た目になる。`list/sakura-script` の分類の中の注意書きの節の見出し 12 個（例: `h3#notes_environmentvariable`。C04・C11）も帯になるので、項目と分けるなら `h3:not([id^="notes_"])` で除く。項目だけに絞るなら、`prepare_site.py` がまとめ頁に入れる `<hr />` の直後の `h3`（`hr + h3`）に限る案を試作で見比べる
- 試作の当て先: `list/sakura-script`（位置: `#bang-lock-repaint`）

- 解く差: D08

### C04
- 題: 注意書きの節を枠の箱に入れる
- 区別: 視認性
- 解く差: D05
- 変更の種類: `サイトを作る処理`・`見た目の指定だけ`
- 見込み: 注意書きの節は原稿の `notes_*.md` の 1 単位である。`list/sakura-script` の 14 個のうち、頁の頭にあるのは 2 個（`notes_escape`・`notes_lifespan`。`h2`）で、残りの 12 個は分類の中の `h3`（例: `h3#notes_environmentvariable`）になる。どれも HTML では、その見出しから次の `<hr />` までの兄弟の要素になる。見た目の指定だけでは「次の `hr` まで」を囲めないので、`prepare_site.py` が `notes_*.md` の単位を `<div class="slp-notes" markdown="1">` で包む（`md_in_html` は有効）。見出しが `div` の中に入るので、見出しの id・¶・目次が変わらないかを試作で確かめる（D17）。包めないときの代わりは、`ブラウザの仕掛け` で読み込みの後に包む案
- 原稿: 要らない（見出しを admonition に書き換える案は原稿が要るので採らない）
- 波及: `notes_*.md` の単位はサイト全体で 16 個（`list/sakura-script` に 14 個、`list/propertysystem` に 2 個）。その全部が箱になる

### C08
- 題: 記述例をひとかたまりの箱に見せる
- 区別: 視認性
- 解く差: D03
- 変更の種類: `見た目の指定だけ`

### C10
- 題: さくらスクリプトに色を付ける
- 区別: 遊び
- 解く差: 差なし（遊び）
- 変更の種類: `サイトを作る処理`・`ブラウザの仕掛け`・`見た目の指定だけ`

## 両立しない組

同じ部分に別の見せ方を当てる候補の組である。決定の段（`decisions.md`）で、組ごとにどちらか 1 つ（または両方を採らない）を選ぶ。

| 組 | 同じ部分 | 違い |
|---|---|---|
| C04 と C11 | `list/sakura-script` などの注意書きの節（`notes_*.md` の単位 16 個） | C04 は点線の枠の箱（視認性）、C11 は尻尾の付いたバルーン（遊び）。どちらも `div.slp-notes` で包む同じ目印を使う |
| C05 と C06 | 対応ベースウェアの段落（1623 段落） | C05 は段落ごと 1 本の帯、C06 はベースウェアの名前ごとの札。どちらも `slp-support` の目印を使う |
| C08 と C18 | 記述例の `h4` と続くコードブロック | C08 は灰色の細い枠の控えめな箱、C18 は濃い紺の帯と左の太い線の強い箱 |
| C26 と C27 | 注釈の見出し（`id` が `notes_` で始まる見出し）の頭 | C26 は添付の色付きの絵、C27 はそれを白黒の線に起こした SVG |

## 重ねるときの依存

両立はするが、片方がもう片方の HTML の形や目印に依る組である。後続 spec への切り分け（同じファイルを触る spec の順）の材料にする。

- C10 → C13: C13 の記述例の見分けは、C10 の `pymdownx.highlight` の設定（言語の印）に依る
- C10 → C09: C10 でコードブロックの HTML の形が変わるので、C09 の指定は両方の形に効くようにする
- C05 → C06: C06 は C05 の段落の目印（`slp-support`）を付けたうえで名前を包む。どちらも `prepare_site.py` の同じ後処理を触る
- C04・C11 と C03・C01: C03 は `notes_` の `h2` を、C01 は `notes_` の `h3`（分類の中の 12 個）を除く。C04・C11 を採らないときも、この除き方はそのままでよい
- C12 → C11: C11 の尻尾の先の絵は、C12 の絵を採ったときだけ足す
- C14 と C16: 頁の種類の印（テンプレートの上書き）を共有できる
